Evaluation design

How to interpret the numbers

Detector parameters were selected using training data. Validation and test predictions were materialised before labels were joined, and transaction and scenario results were evaluated separately.

  1. 01
    Fit and select

    Use the synthetic training split only.

  2. 02
    Freeze predictions

    Generate held-out evidence without label inputs.

  3. 03
    Join truth

    Calculate validation and test confusion metrics.

  4. 04
    Audit evidence

    Verify every referenced transaction and exported result.

Interpretation boundary

Successful prototype, not a production AML system

The results demonstrate the project idea on a planted synthetic design. Independent, temporally separated real-world validation is still required.

01

Synthetic labels

Headline results describe planted behaviours, not real financial-crime prevalence.

02

Separate data meanings

PaySim fraud and IBM AML are external context and are not pooled into the headline score.

03

Training-selected thresholds

Parameters require controlled recalibration before use with another population.

04

Operational costs

Investigation capacity, alert priority and reviewer cost were not simulated.

05

Bounded scale

Graph benchmarking stops at the —-row synthetic test population.

06

Governance work

Fairness, privacy, drift and independent compliance review remain future work.
