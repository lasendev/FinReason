# FinReason

FinReason is an explainable financial anomaly detection project built around temporal transaction graphs, bounded breadth-first and depth-first search, statistical baselines, and forward-chaining rules. Each alert retains the transaction and rule evidence used to produce it.

The main experiment uses a chronological train/validation/test split of the bundled synthetic dataset. PaySim and IBM AML are used as separate preprocessing and scalability benchmarks; their labels are not mixed into the headline score.

## Headline result

The selected `GRAPH_ROLLING_HYBRID` combines 24-hour graph motifs with a causal 48-hour rolling frequency detector. On the held-out FinReason synthetic laundering test labels it produced:

| Metric | Result |
|---|---:|
| Precision | 97.82% |
| Recall | 87.38% |
| F1 score | 92.31% |
| False-positive rate | 0.13% |
| Scenario detection rate | 70.99% |

That is 1,212 true positives, 27 false positives, and 175 false negatives across 22,309 test transactions. These are research results on planted synthetic labels, not evidence of production AML performance.

## Requirements

- Python 3.10 or newer (tested with Python 3.10)
- Internet access for the first full run
- At least 2 GB of free disk space for the PaySim and IBM AML benchmark data

The repository includes the primary FinReason synthetic dataset. The first full run downloads roughly 1 GB of external benchmark data and caches it under `workspace/data/`; later runs reuse the cache.

## Setup

From the project directory:

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install --upgrade pip
python -m pip install -r requirements.txt
```

On Windows, activate the environment with:

```powershell
.venv\Scripts\activate
```

## Run the project

Run the tests and then execute all notebook cells:

```bash
python scripts/run_project.py
```

The runner stops on a failed test or notebook error. A successful run ends with:

```text
Ran 66 tests ... OK
Notebook complete: 93 code cells executed with no errors.
FinReason completed successfully.
```

Useful alternatives:

```bash
# Fast code check without downloading the external benchmark data
python scripts/run_project.py --tests-only

# Execute only the notebook
python scripts/run_project.py --notebook-only

# Work through the notebook interactively
jupyter notebook FinReason_Implementation.ipynb
```

To place the large data cache outside the repository, set `FINREASON_DATA_DIR` before running:

```bash
FINREASON_DATA_DIR=/path/to/finreason-data python scripts/run_project.py
```

## Present the results

The dashboard is plain HTML, CSS, and JavaScript and has no web dependencies. Its result values are not stored in the HTML: the browser reads the CSV and JSON files generated by `FinReason_Implementation.ipynb` under `workspace/outputs`. Run the project first, then serve it from the repository root:

```bash
python -m http.server 8000
```

Open [http://localhost:8000/frontend/](http://localhost:8000/frontend/) and stop the server with `Ctrl+C`.

Do not open `frontend/index.html` directly as a local file. Browsers restrict local data loading, so use the command above. A green message at the top confirms that the latest notebook outputs loaded; a red message explains how to regenerate them if a source file is missing.

## What to check after a run

These files provide the shortest verification path:

1. `workspace/outputs/tables/section12_final_scorecard.csv` — final five-variant comparison; check the test `GRAPH_ROLLING_HYBRID` row.
2. `workspace/outputs/audit_trails/section11_testing_report.json` — unit, integration, determinism, and scalability checks.
3. `workspace/outputs/tables/section10_tradeoffs.csv` — detection quality, alert burden, runtime, and audit completeness.
4. `workspace/outputs/audit_trails/section12_artifact_manifest.csv` — SHA-256 manifest for the final evidence pack.
5. `frontend/index.html` — presentation view of the main findings and limitations.

## Method boundaries

- Threshold selection uses training data only; validation and test labels remain held out.
- The 48-hour detector stores only active per-account events in deques, avoiding a multi-day in-memory NetworkX graph.
- PaySim fraud is not relabelled as money laundering.
- IBM AML and PaySim results remain source-specific and are excluded from the FinReason headline metrics.
- Alerts are review indicators with traceable evidence, not legal determinations.
